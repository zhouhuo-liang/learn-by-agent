## 一、本课目标

L17 的主线是：

```text
key 经过哈希函数得到桶下标
    ↓
不同 key 可能得到同一个桶下标（冲突）
    ↓
用拉链法把冲突元素放在同一个桶里
    ↓
实现查找、插入、删除
    ↓
用负载因子判断是否应该扩容
    ↓
rehash：增加桶并重新分配所有旧元素
```

本课实现的哈希表保存整数，语义类似一个 `set`：同一个值最多出现一次。

---

## 二、为什么需要哈希表

数组按下标访问很快：

```text
O(1)
```

但数组下标必须是连续的整数。哈希表用哈希函数把 key 变成桶下标：

```text
key → hash function → bucket index
```

然后只需要检查一个桶。

如果元素分布均匀，平均查找时间接近：

```text
O(1)
```

---

## 三、哈希函数

本课使用取模：

```cpp
index = value % bucket_count;
```

初始桶数量为 `7`：

| key | 计算 | 桶下标 |
|---:|---|---:|
| 10 | `10 % 7` | 3 |
| 20 | `20 % 7` | 6 |
| 3 | `3 % 7` | 3 |
| 17 | `17 % 7` | 3 |
| 24 | `24 % 7` | 3 |

`10、3、17、24` 都进入桶 `3`，这就是哈希冲突。

### 负数处理

C++ 中负数取模可能得到负数：

```cpp
-3 % 7 == -3
```

数组不支持负下标，所以：

```cpp
if (index < 0) {
    index += n;
}
```

得到：

```text
-3 + 7 = 4
```

保证桶下标在：

```text
0 ~ n-1
```

---

## 四、哈希冲突

哈希冲突是：

> 不同 key 经过哈希函数后，得到相同的桶下标。

冲突无法完全避免。例如桶数量是 7 时，所有相差 7 的倍数都会落到同一个桶：

```text
3, 10, 17, 24, 31, 38, ...
```

原因不是数组不够大，而是：

```text
可能的 key 数量远多于桶数量
```

所以必须设计冲突处理策略。

---

## 五、拉链法

本课使用拉链法：

```cpp
vector<vector<int>> buckets;
```

外层 `vector` 保存所有桶，每个桶是一个 `vector<int>`。

例如：

```text
bucket 3: 10 3 17 24
bucket 6: 20
```

查找 `17` 时：

1. 计算 `17 % 7 = 3`
2. 只扫描 `bucket 3`
3. 在桶内找到 `17`

查找 `5` 时：

1. 计算 `5 % 7 = 5`
2. `bucket 5` 是空的
3. 返回 `false`

拉链法的缺点是冲突过多时，桶内链会变长，查找退化。

## 六、哈希表结构

```cpp
struct hash_table {
    vector<vector<int>> buckets;
    int count = 0;

    hash_table() {
        buckets.resize(7);
    }
};
```

`buckets.resize(7)` 创建 7 个空桶。

`count` 记录当前保存了多少个不同元素。

---

## 七、查找 `contains`

```cpp
bool contains(int value) {
    int index = hash_value(value);

    for (int x : buckets[index]) {
        if (x == value) {
            return true;
        }
    }

    return false;
}
```

步骤：

1. 计算桶下标
2. 只遍历这个桶
3. 桶内找到目标，返回 `true`
4. 遍历完仍未找到，返回 `false`

平均复杂度：

```text
O(1)
```

最坏复杂度：

```text
O(n)
```

---

## 八、插入 `insert`

```cpp
void insert(int value) {
    if (contains(value)) {
        return;
    }

    if (static_cast<double>(count + 1) / buckets.size() > 0.75) {
        rehash(buckets.size() * 2 + 1);
    }

    int index = hash_value(value);
    buckets[index].push_back(value);
    count++;
}
```

先判断重复：

```cpp
if (contains(value)) {
    return;
}
```

因此同一个值只会保存一次。

然后在插入前判断扩容：

```cpp
static_cast<double>(count + 1) / buckets.size() > 0.75
```

需要计算 `count + 1`，因为我们判断的是“插入这个新元素之后”的负载因子。

最后：

```cpp
buckets[index].push_back(value);
count++;
```

把元素放到对应桶的末尾，并更新计数。

---

## 九、删除 `remove`

```cpp
bool remove(int value) {
    int index = hash_value(value);

    for (size_t i = 0; i < buckets[index].size(); i++) {
        if (value == buckets[index][i]) {
            buckets[index].erase(buckets[index].begin() + i);
            count--;
            return true;
        }
    }

    return false;
}
```

步骤：

1. 计算桶下标
2. 扫描对应桶
3. 找到目标后使用 `erase` 删除
4. 更新计数并返回 `true`
5. 找不到返回 `false`

`erase` 会让后面的元素向前移动：

```text
删除前：10 3 17 24
删除 3：10 17 24
```

删除成功：

```text
remove(3) -> 1
```

删除不存在元素：

```text
remove(99) -> 0
```

---

## 十、负载因子

```cpp
double load_factor() const {
    return static_cast<double>(count) / buckets.size();
}
```

公式：

```text
load factor = count / bucket_count
```

当前：

```text
count = 4
bucket_count = 7
load factor = 4 / 7 ≈ 0.571429
```

负载因子越高，桶平均越拥挤，查找越慢。

本课阈值：

```text
0.75
```

超过阈值时触发 rehash。

---

## 十一、rehash

```cpp
void rehash(size_t new_capacity) {
    if (new_capacity == 0) {
        return;
    }

    vector<vector<int>> old_buckets = buckets;

    buckets.clear();
    buckets.resize(new_capacity);
    count = 0;

    for (size_t i = 0; i < old_buckets.size(); i++) {
        for (int value : old_buckets[i]) {
            insert(value);
        }
    }
}
```

### 为什么必须重新插入

桶数量改变后，取模结果会改变：

```text
17 % 7  = 3
17 % 15 = 2
```

旧元素原本在桶 3，扩容后应该放到桶 2。因此必须重新计算每个元素的位置。

### 流程

1. 保存旧桶 `old_buckets`
2. 清空原桶
3. 调整为新容量
4. 将 `count` 重置为 0
5. 遍历旧桶，把每个值重新 `insert`

### 扩容前

```text
count = 4
buckets = 7
load factor ≈ 0.571429
```

插入 `1` 后：

```text
count = 5
load factor ≈ 0.714
```

插入 `2` 时：

```text
(5 + 1) / 7 ≈ 0.857 > 0.75
```

触发：

```text
7 → 15
```

扩容后：

```text
count = 6
buckets = 15
load factor = 6 / 15 = 0.4
```

### 验证

扩容后仍然能查到所有元素：

```text
contains(10) = 1
contains(17) = 1
contains(20) = 1
contains(24) = 1
contains(1)  = 1
contains(2)  = 1
```

最终：

```text
count after rehash: 6
```

## 十二、容量策略

本课使用：

```cpp
buckets.size() * 2 + 1
```

扩容序列：

```text
7 → 15 → 31 → 63 → ...
```

不直接乘 2，是为了减少桶数量与 key 之间形成固定规律的概率。

## 十三、复杂度

| 操作 | 平均 | 最坏 |
|---|---:|---:|
| `contains` | `O(1)` | `O(n)` |
| `insert` | 均摊 `O(1)` | `O(n)` |
| `remove` | `O(1)` | `O(n)` |
| `rehash` | `O(n)` | `O(n)` |

`rehash` 一次要搬移所有元素，所以单次是 `O(n)`。
但它不会每次插入都发生，因此插入的均摊复杂度仍可看作 `O(1)`。

## 十四、与 STL 的关系

本课的哈希表是整数集合，类似：

```cpp
unordered_set<int>
```

如果保存“键 → 值”：

```cpp
unordered_map<string, int>
```

例如词频统计：

```cpp
unordered_map<string, int> frequency;

frequency["apple"]++;
frequency["banana"]++;
```

哈希表的常见用途：

- 判断元素是否出现过
- 词频统计
- 缓存
- 去重
- 快速建立映射关系

## 十五、易错点与纠正

### 1. 冲突不等于 key 相同

冲突是不同 key 落到同一个桶：

```text
10、17、24 都进入 bucket 3
```

但它们在桶内仍然是不同的元素。

### 2. 负数下标

```cpp
-3 % 7
```

可能得到负数，需要：

```cpp
if (index < 0) {
    index += n;
}
```

### 3. rehash 不是只增加桶

必须重新插入所有旧元素，因为桶数量改变会影响哈希结果。

### 4. 不要只看 count 判断拥挤

需要同时看元素数量和桶数量，所以使用负载因子。

### 5. 平均不是保证

哈希表平均是 `O(1)`，但冲突严重时最坏是 `O(n)`。

## 十七、结课结论

本课最重要的五句话：

1. 哈希表通过哈希函数把 key 映射到桶下标。
2. 不同 key 落到同一个桶叫冲突，本课用拉链法处理。
3. 平均查找、插入、删除为 `O(1)`，冲突严重时退化为 `O(n)`。
4. 负载因子超过 `0.75` 时扩容，避免桶内链过长。
5. rehash 必须重新插入所有元素，因为桶数量变化会改变哈希结果。
