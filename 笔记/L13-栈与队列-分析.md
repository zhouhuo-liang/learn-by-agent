## 一、你的代码逐段点评

### 1. Stack 结构体 ✅ 实现正确

```cpp
struct Stack {
    char data[100];
    int top = -1;                     // -1 表示空栈
    void push(char v) {
        if (top >= 99) cout << "栈满了！" << endl;
        else { data[++top] = v; }     // 先 top+1，再放值
    }
    char pop() {
        if (top < 0) { cout << "栈空的！" << endl; return -1; }
        return data[top--];           // 先取值，再 top-1
    }
    bool empty() { return top < 0; }
};
```

**点评**
- ✅ `top = -1` 表示空栈，初始化正确
- ✅ `data[++top] = v`（先加后放）、`data[top--]`（先取后减）：两个顺序都对，这是最容易写错的地方
- ✅ 满栈判断 `top >= 99` 正确（数组下标是 0~99）
- ✅ 空栈判断 `top < 0` 正确
- ✅ 你把 `data` 改成 `char`，成功把栈迁移到"字符"场景 —— 这是很好的举一反三
- 💡 小知识：空栈时 `pop()` 返回 `-1` 表示"没有值"。工业代码里更常用异常或 `optional`，但学习阶段这样就够用

### 2. Queue 结构体 ✅ 实现正确

```cpp
struct Queue {
    int data[100];
    int head = 0, tail = 0;
    void enqueue(int v) {
        if (tail >= 100) cout << "队列满了！" << endl;
        else { data[tail++] = v; }    // 放到队尾，尾巴后移
    }
    int dequeue() {
        if (head >= tail) { cout << "队列空的！" << endl; return -1; }
        return data[head++];          // 从队头取走，头后移
    }
    bool empty() { return head >= tail; }
};
```

**点评**
- ✅ 用 `head` / `tail` 两个下标：入队在尾、出队在头，**FIFO 语义完全正确**
- ✅ 空队列判断 `head >= tail` 正确
- ✅ 三个操作都是 **O(1)**，没有搬移元素 —— 这是高效写法
- ⚠️ **已知局限（假溢出）**：出队多次后 `head` 一直变大，`tail` 也可能涨到 100。即使前面已经空出位置，也无法再入队了。
  - 真正的工程实现是**环形队列**（下标用 `% 100` 绕回来）或用链表
  - 这是很好的进阶挑战，我们以后可以专门做一次

### 3. main 的演示 ✅ 完全正确

```cpp
Stack s;
s.push('a'); s.push('b'); s.push('c');   // 栈：a b c
while (!s.empty()) cout << s.pop();      // 输出 c b a  ← LIFO 铁证

Queue q;
q.enqueue(10); q.enqueue(20); q.enqueue(30);
while (!q.empty()) cout << q.dequeue();  // 输出 10 20 30 ← FIFO 铁证
```

- ✅ 栈：进 `a,b,c` → 出 `c,b,a`（**反着出**）
- ✅ 队列：进 `10,20,30` → 出 `10,20,30`（**顺着出**）
- 这两个演示就是 LIFO 与 FIFO 最直接的证据

### 4. 括号匹配（挑战题）⚠️ 结构好，但有一处逻辑漏洞

```cpp
Stack c;
char c_test1[7] = { '(', '(', ')', ')', ',', ')' , ')' };
for (int i = 0; i < 7; i++) {
    if (isMatch_l(c_test1[i])) { c.push(c_test1[i]); }
    else if (isMatch_r(c_test1[i])) { char cn = c.pop(); }
}
if (c.empty()) { cout << "匹配"; }
else { cout << "不匹配"; }
```

**先说优点**
- ✅ 思路方向完全正确：左括号入栈、右括号出栈、最后看栈是否空
- ✅ 你主动拆出 `isMatch_l` / `isMatch_r` 两个辅助函数 —— 这是很好的**模块化意识**（L04 的思想你内化了）
- ✅ 主动挑战加分题，值得表扬

**问题 1（严重）：遇到 `)` 时没有检查栈是否为空**

反例：输入 `"))"`，你的程序会怎么走？
- 第 1 个 `)` → 栈是空的，你照样调用 `pop()`（弹出 -1，报"栈空的！"）
- 第 2 个 `)` → 同样弹了个空
- 循环结束，栈是空的 → 你判断"**匹配**" ❌

**正确答案是不匹配**——因为没有左括号能被这两个右括号配对。

**问题 2（小）**：`char cn = c.pop();` 取出来的值从头到尾没用到，可以直接写 `c.pop();`

**问题 3（小）**：测试数组里有个 `','`（逗号字符）。它既不是 `(` 也不是 `)`，会被两个判断都跳过，不影响结果但让测试不清晰。建议直接用字符串写测试用例。

**正确写法**

```cpp
bool check_brackets(const string& s) {
    Stack st;
    for (char ch : s) {
        if (ch == '(') {
            st.push(ch);
        }
        else if (ch == ')') {
            if (st.empty()) return false;   // ← 关键：没有左括号可配，立刻失败
            st.pop();
        }
    }
    return st.empty();                      // 全部处理完后必须一个不剩
}
```

**建议的测试用例**

| 输入 | 期望结果 | 说明 |
|---|---|---|
| `()` | 匹配 | 最简单的一对 |
| `(())` | 匹配 | 正常嵌套 |
| `(()` | 不匹配 | 左括号多了（栈里还剩一个） |
| `))` | 不匹配 | 右括号多了（旧版本会判错！） |
| `)(` | 不匹配 | 顺序错误 |

## 二、概念精修：栈 vs 队列

你一开始答的是"存储和输出顺序不同"——方向对，但太含糊。准确说法：

| 结构 | 规则 | 进 / 出 顺序 | 生活例子 |
|---|---|---|---|
| **栈 Stack** | **LIFO**（后进先出） | 进 `1,2,3` → 出 **`3,2,1`**（相反） | 一摞盘子 |
| **队列 Queue** | **FIFO**（先进先出） | 进 `1,2,3` → 出 **`1,2,3`**（相同） | 排队买饭 |

**一句话记忆**：栈是"**反着出**"，队列是"**顺着出**"。

**典型应用场景**
- 栈：函数调用栈、浏览器"后退"、Ctrl+Z 撤销、括号匹配、表达式求值、DFS 深搜
- 队列：排队叫号、打印机任务队列、消息队列、BFS 广搜、任务调度

## 三、复杂度小结

| 操作 | 复杂度 | 说明 |
|---|---|---|
| 栈 push / pop | O(1) | 只动栈顶 |
| 队列 enqueue / dequeue | O(1) | 只动 head / tail |
| （错误做法）用 vector.erase(0) 出队 | O(N) | 每出队一次都要搬移全部剩余元素，很慢 |

> 记住：能用 head/tail 两个下标解决的问题，不要用"搬移元素"解决。
